## 2. 【最大の成果】連接コスト行列 (MTX1) の完全復元

### 2.1 aqdic.bin の全体構造 (全セクション走査で確定)

```
0x000000 UNKD (412)        ┐
0x0001a4 POSD (1208)       │ 前付き小辞書
  0x0001ac POS1 (1200)     │
0x000664 MCGD (36820)      │  HDR1 / TRI1 / MAP1 / TOK1
0x009640 MTXD (2794260)    ┘
  0x009648 MTX1 (2794252)  ← ★ 連接コスト行列
0x2b395c MSTD (7015252)      本体辞書 HDR1 / TRI1 / MAP1 / TOK1
```
（`MSTD` が本体。`MTXD/MTX1` だけが本体辞書の外にある独立セクション。）

### 2.2 形式と索引

```
MTX1 : [u16 w=1182][u16 h=1182][w*h int16]   (4 + 1182*1182*2 = 2794252 = MTX1 size と一致)
連接コスト(prev → next) = M[next.pos & 0x7fff][prev.pos & 0x7fff]
```
* 全レコード (engine の `decodeRecords` が数えて 384100 件、解析ツールは空読みレコードも含めて 384657 件) の
  `pos & 0x7fff` は **0..1181 に収まり distinct=1181, max=1181** → 行列の次数 1182 と一致
  (`eval/tools/posidx.mjs` で再現)。
* **index 0 だけ未使用** → 文頭/文末 (BOS/EOS)。
* `pos` そのものは 1447 種あるので `pos & 0x7fff` が正しい射影 (`pos` の bit15 は連接クラスではない別のフラグ)。

### 2.3 決め手になった手法 = 「公式 DLL の辞書イメージを書き換える差分実験」

`work/probes/_official.mjs` を改造し **`eval/tools/official_mut.mjs`** を作成。v86 上の公式 DLL は
`AqKanji2Koe_Create_Ptr` に渡した辞書バッファを**その場参照**し続けるため、
`emu.mem_write(dictAddr + off, ...)` で 1 バイト書き換えると**即座に**挙動が変わる
(再 Create も不要)。これで「辞書のどのバイトが何を決めているか」を直接観測できる。

確定に使った実験:

| 実験 | 結果 |
|---|---|
| M[204][981] (昨夜→は) を +32767 | `ユンベ'ワ` → `サク'ヤワ` に反転 |
| M[981][204] を +32767 (逆向き) | **変化なし** → 向きは `M[next][prev]` で確定 |
| M[999][1004] (度→何) を +32767 | `ナ'ンドモ` → `ナニ'ドモ` に反転 |
| 年トシの cost (u16@+2) を 8630→1 | `十年前` → `ジュートシ` → **u16@+2 が語コストで確定** |
| 行列全体を +29976 に飽和 | 公式出力が「語コスト和最小」の素朴な分割に退化 (十年前→ジューネンゼン, 昨夜は→サクヤワ, 雪が→ソソガ) |
| extra バイトを全部 0xff / 0x00 | 239 文中 **179 / 117 文が変化** → extra はアクセント結合データ (連接コストではない) |

### 2.4 実装 (`core/engine.js`)

* `parseConnMatrix()` が `MTXD/MTX1` を読み `Int16Array` 化 (タグ検証 + 走査フォールバック、無ければ `null`)。
* `_connCost(prevIdx, prevNode, cand, rec)` が行列を引く。行列が無い辞書では旧近似に自動フォールバック
  (バグ修正: 以前は `connW=0` で全レコードを捨てていた。`fb34d1d`)。
* **`segmentViterbi` を「状態 = (文字位置, 直前語の品詞インデックス)」に修正**。
  従来は位置ごとに最良 1 個しか残しておらず、連接コストが直前品詞に依存するため原理的に不正解だった。
  実例「何度も」: 位置 1 では 何ナニ(5251) < 何ナン(8297) だが、度への連接が −4464 vs −10114 で逆転し公式は ナン を選ぶ。
* 文末は EOS への連接 `M[0][last]` を加算 (`opts.eosCost=false` で無効化可)。
* `opts.connCost: 'matrix'(既定) | 'approx'(旧近似) | 'off'` で旧挙動も選択可。

## 3. 【未解明】extra バイト = アクセント結合データ

### 3.1 形式

record header は `[pos u16][cost u16][flag u8][moraByte u8][accByte u8]`、続いて `mora` 個のカナコード、
そのあと **flag の下位ニブル個**の extra バイト。

| flag | extra バイト数 | レコード数 |
|---|---|---|
| 0x40 | 0 | 281903 |
| 0x41 | 1 | 101876 |
| 0x42 | 2 | 161 |
| 0x43 | 3 | 160 |
| 0x44 | 3 (= (flag&0x0f)−1) | 3 |
| 0x45 | 4 (= (flag&0x0f)−1) | 554 |

実例: `は`=`60 83 a1`, `が`(pos33039)=`60 83 a1`, `を`=`60 83 a1`, `に`=`83 60`, `の`=`83 a1`,
`て`=`80 a1`, `た`=`80 a2 c3`, `です`=`64 83 a1`, `ます`=`91`, `すぎ`=`91 b2`, `ながら`=`71 91 b1`。

### 3.2 分かったこと (実測)

1. **extra は連接コストではない**。連接コストは MTX1 にあり、extra はアクセント側のデータ。
2. **核位置を決めるのは「後ろに来る語」の extra**。頭語の extra を 0..255 全走査しても
   ほぼ挙動が変わらない (0x4f/0x50/0x51 の 3 値だけが例外)。
3. 付属語の extra バイトを全走査すると、出力は**階段関数**になる。1 例 (「話します」の `ます` の extra):

   | extra | 出力 | 挙動 |
   |---|---|---|
   | 0x00-0x3f, 0x60-0x7f, 0xa0-0xdf など (201 値) | `ハナ'シマス` | 頭のアクセントのまま |
   | 0x42,0x43,0x4a,0x4d,0x4e,0x59,0x85,0x8d,0x91,0x9c,0xe5,0xed,0xf1,0xfc | `ハナシマ'ス` | 付属語自身のアクセント |
   | 0x44,0x46,0x49,0x51,0x93-0x99,0x9b,0xf3-0xf9,0xfb | `ハナシマス` | 平板 |
   | 0x45,0x47,0x48,0x4b,0x5f,0x8b,0x8c,0x90,0x9d,0xeb,0xec,0xf0,0xfd | `ハナシ'マス` | 頭の最終拍 |
   | 0x8e,0x92,0xee,0xf2 | `ハナシマス'` | 句末 (尾高) |
   | 0x4c,0x4f,0x52 / 0x53 | `ハナ'シ/マ'ス` | アクセント句が 2 つに分かれる |

4. しかし **byte → 挙動の写像は頭語にも依存する** (「読みます」と「話します」で同じ byte が違う挙動)。
   ビット欄 (`byte & 0x1f` など) では説明できず、**疎なルックアップテーブル**を引いているように見える。
5. 有効な extra 値は辞書内で疎 (表 §3.1: flag 0x42 は 161 件、0x43 は 160 件、0x44/0x45 は 3/554 件のみ)。
   任意値へ書き換えると「未定義エントリ」を引くため挙動が乱れる、という解釈が最も整合的。

### 3.3 証偽できなかった / できた仮説

| 仮説 | 判定 |
|---|---|
| extra = 連接コスト (左/右連接コスト行列) | **証偽**。連接は MTX1 にあり、extra はアクセント結合 |
| extra は 1 個の整数を可変長符号化したもの | **否定的**。`& 0x7f` の値列として階段関数にはなるが、同じ値で頭語により挙動が変わる |
| extra は品詞の再掲 | **証偽** (`は`/`が`/`を` は同じ extra だが `買い+が` だけ核が付く) |
| extra は読みの別表記 | **証偽** (0xa1 以降はカナコード表の範囲外) |

**結論**: extra はアクセント結合テーブルの索引である可能性が高いが、**テーブル本体の同定は未完了**。
残る不一致 8 文はすべてこのテーブル由来。

## 4. 実装したアクセント句規則 (すべて公式 DLL への対拍で確認)

`core/kanji_accent.js` の `phraseCut()` / `groupStream()`。

### 4.1 アクセント句のまとめ方 (grouping)

1. アクセント句 = 自立語 + 後続付属語。`AUX_POS` (pos) と `AUX_SURF` (表層) で付属語を判定。
2. **「て/で + 補助動詞」は補助動詞が新しいアクセント句を始める** (`HOJO_SURF`)。
   実測: `降っているので` → `フ'ッテ+イル'ノデ` / `なってきた` → `ナ'ッテ+キ'タ` /
   `食べてしまった` → `タ'ベテ+シマッタ` / `履いています` → `ハイテイマ'ス` (結果は不変)。
3. **「よう」はイ形容詞の直後以外では新しい句を始める**。
   実測: `悪い+ようです` → `ワル'イヨーデス` (1 句) に対し
   `食べた+ようです` → `タ'ベタ+ヨ'ーデス` / `降る+ようです` → `フ'ル+ヨ'ーデス` /
   `学生+の+ようです` → `ガクセーノ+ヨ'ーデス` / `静かな+ようです` → `シ'ズカナ+ヨ'ーデス` /
   `毎日+の+ように` → `マイニチノ|ヨ'ーニ`。
4. **複合名詞は 2 語まで** (3 語以上の連鎖をしない)。
   実測: `十年前` → `ジュ'ーネン+マエ` / `十年前に` → `ジューネン+マ'エニ`。
5. `ない` 系は助詞の後ろでは自立語 (形容詞「無い」)。伝聞「そうです」は終止形の後で別句 (前エージェントの規則)。

### 4.2 核位置 (phraseCut) — 今セッションで直した/足したもの

| # | 規則 | 実測根拠 |
|---|---|---|
| 1a | **「ん」は直前の語の最終拍へ核を移す (頭が平板でも移る)** | `行かん`→`イカ'ン` / `読まん`→`ヨマ'ン` / `ませ+ん`→`マセ'ン` |
| 1b | 「ぬ/ず」は**頭が有核のときだけ**語幹最終拍へ | `行かぬ`→`イカヌ` / `読まぬ`→`ヨマ'ヌ` / `行かず`→`イカズ` / `読まず`→`ヨマ'ズ` |
| 2 | `NO_TAIL` で頭が平板のとき `return -1` をやめ規則 (6) にフォールバック | `行かなかった`→`イカナ'カッタ` / `行かなくて`→`イカナ'クテ` |
| 3 | `AUX_SURF` に `せ/なかっ/なけれ/なく/なかろ` を追加 | `読ませました`→`ヨマセマ'シタ` / `起きなければ`→`オキ'ナケレバ` |
| 4 | `NOUN_POS` に 33767 (度/年), 995 (語/度/年/前) を追加 | `何度も`→`ナ'ンドモ` / `外国語を`→`ガイコクゴオ` |
| 5 | 規則 (6) は**付属語だけ**を見る (複合名詞の後部のアクセントを拾わない) | `外国+語`→`ガイコクゴ` (拾うと `ガイコクゴ'`) |
| 6 | 規則 (5) の尾高化は直前が「自前の核を持つ付属語」なら適用しない | `買った+ばかり+の`→`カッタバ'カリノ` |
| 7 | `AUX_OWN_ACCENT` + 尾高判定: 「すぎ」は**頭が尾高 (accent==mora)** なら すぎ の 2 拍目、それ以外は連接行列が選んだレコードの accent | `難し(a4m4)+すぎ`→`ムズカシスギ'テ` / `高(a2m2)+すぎ`→`コースギ'` / `入れ(a0)+すぎ`→`イレス'ギタ` / `飲み(a1m2)+すぎ`→`ノミス'ギ` |
| 8 | `AUX_POS` に 33763 (たち), 助動詞よう (1096/1146/1167) を追加 | `生徒+たち+に`→`セ'ートタチヌ` |
| 9 | デバッグ用 `debugPhrases` が変換本体と**別の古い句分け実装**を持っていたのを `groupStream()` に一本化 | 調査を誤らせる stale 複製だった (挙動は不変) |

## 5. 棄却した仮説・負の結果 (前エージェント分も含む)

### 今回のセッションで追加

| 仮説 | 結果 |
|---|---|
| extra バイトが連接コスト行列 | **証偽**。連接は MTX1 セクションにあった |
| 連接コストは語コストと単純加算で、位置ごとの最良 1 個の DP で足りる | **証偽** (何度も)。状態 = (位置, 品詞) が必要 |
| MTX1 を `pos` そのもので索引する | **証偽** (pos は 1447 種)。`pos & 0x7fff` (1181 種, max 1181) が正しい |
| MTX1 の向きは `M[prev][next]` | **証偽**。差分実験で `M[next][prev]` と確定 |
| extra を 1 バイトずつ独立に読めば規則が分かる | **否定的**。byte→挙動は頭語にも依存し、単純な関数にならない |

| extra バイトの写像は頭語に依存しない | **証偽**。ただし同一の (accent, mora) を持つ頭同士では完全に一致する (読み a1m2 と 食べ a1m2 の 256 値格子が全セル一致) → 頭のアクセントクラスには依存する |
| EOS 連接 `M[0][last]` が結果を変える | **この 227 文では影響なし** (DEV/保留とも同値) |
| 行列全体を飽和させると公式の分割が分かる | **有効** (検証手段として採用)。語コスト和最小に退化する |
| 連接行列が無い辞書でも既定のままでよい | **証偽 (バグ)**。`connW=0` で全レコードを捨てていた → `useMatrix` で分岐 |

## 8. 次の一手 (提案)

1. **extra バイト → 結合規則テーブルの同定 (最優先)**。今回確立した差分実験をさらに押し進める:
   * v86 の CPU レベルでメモリ読みを観測できれば、DLL が MTX1 以外のどこを読むか直接分かる。
     現状 `V86Emu.set_hook` はコードアドレス単位のフックしか無いため、`cpu.mem8` をラップするか
     JIT キャッシュを無効化した逐次実行で読み出し番地を記録するハックが要る。
   * あるいは DLL 内のテーブル (256 エントリ程度と推定) を、extra 値を全走査したときの
     挙動パターン (上表の 7 種) と照合して同定する。
2. **アクセント結合の大規模学習**。`tools/seq.mjs` の記録使用オラクルと `tools/official_mut.mjs` を
   組み合わせ、`(頭の pos, 頭の accent, 頭の mora, 付属語の extra)` → 核位置 の表を
   数百〜数千の最小対で実測して学習する。今回は 1 語ずつの規則帰納で 96.5% まで来たが、
   残りは「同一パラメータで結果が違う」領域なので規則では表現できない。
3. **`pos & 0x7fff` の bit15 の意味**。連接クラスではないフラグ (付属語性/活用型?) を同定すると、
   `AUX_POS` の手動集合を pos の規則で置き換えられる可能性がある。
4. コーパス拡大 (現在 DEV140 + 保留87 = 227 文)。特にサ変動詞・複合動詞・助数詞を増やす。
