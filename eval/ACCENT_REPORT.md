## 3. 実装した規則 (すべて公式 DLL への対拍で確認)

### 3.1 構造の逆転 (最大の効果)
1. **アクセント句モデル** (`accentModel='phrase'`, 既定)。
   公式出力は `/` `+` `、` `。` で区切られたアクセント句ごとに `'` が**高々 1 つ**
   (2954 句整列で確認, 核 0 が 28.9%)。句 = 自立語 + 後続付属語。これが旧 `dedupe`
   (隣接核を抑制) の素朴な近似を置き換える。
2. **分かち書きを Viterbi (語コスト和最小) に** (`segmentMode='viterbi'`, 既定)。
   旧 dedupe モデルでは効果が無かった (負結果) が、句モデル導入後は分かち書きが核位置に直結するため
   48.6% → 64.3% と大きく効いた。

### 3.2 核位置の規則
1. 有核の頭 + 付属語 → 頭の核 (山+は → ヤマ'ワ)
2. 平板の頭 + 付属語 → 最初の有核付属語の位置 (飴+まで → アメマ'デ / 会社+です → カイシャデ'ス)
3. 上書き助動詞 (位置 = 助動詞先頭 + N):
   ます+1 / ません+2 / まし+1 / ませ+2 / ましょ+2 / たい+1 / れる+1 / られる+2 /
   せる+1 / させる+2 / られ+1 / させ+1 / ながら+1 / そう+1 / やすい系+2 / すぎ+2 / でしょ+2
   (核は「助動詞の拍数-1」: られ=2拍→+1, られる=3拍→+2。後方優先で ます > すぎ)
4. 無核の付属語: た・て・だ・で・ば・ない・ぬ・ん・なけれ系 / 単独句首では辞書の accent を使う
5. 動詞未然形 + ない/なけれ → 語幹最終拍 (食べ+ない → タベ'ナイ / 起き+なけれ+ば → オキ'ナケレバ)。
   ただし形容詞…ク + ない は頭の核のまま (高く+ない → タカ'クナイ)
6. 平板の用言 + 接続/終助詞 {か,ぞ,さ,な,わ,ぜ,の,ば,ので,のに,けど,けれど,です,も,は,から}
   → 直前の語の最終拍 (行く+か → イク'カ / すれ+ば → スレ'バ / 遅れている+ので → オクレテイル'ノデ /
   散歩する+の → サンポスル'ノ / 会社から+も → カイシャカラ'モ / 聞い+て+も → キイテ'モ)。
   名詞は対象外 (会社+か → カイシャカ / 会社+は → カイシャワ)。
   ね/よ は直前が付属語のときだけ (して+ね → シテ'ネ, 行く+ね は平板)。
7. イ形容詞: 核 = 語幹最終拍 (終止形/連用形 = 最終拍-1, かっ形 = -2, けれ形 = -3)。
   おいしい+です → オイシ'イデス / おいしかっ+た → オイシ'カッタ / 若く → ワカ'ク。
   平板イ形容詞 + 無核助詞 → 語幹最終拍 (おいしい+と → オイシ'イト)。有核助詞があればそちらが勝つ (遅く+まで → オソクマ'デ)。
8. 尾高名詞 + の → 平板化 (山+の → ヤマノ)
9. 複合名詞 (名詞+名詞) → 後部要素が 3 拍以上なら接合部の第 1 拍
   (天気+予報 → テンキヨ'ホー / 電話+番号 → デンワバ'ンゴー)。
   ただし時間名詞 (毎日/昨日/毎週 pos 984, 33752) は複合しない (毎日+日本語 → ヌ'イヌチ/ヌホンゴオ)
10. 文末の「そうです」(伝聞) は別アクセント句 (行く+そうです → イク|ソ'ーデス)。
    様態は切れない (降りそうです → オリソ'ーデス)
11. 助動詞「う」はオ段の直後で長音「ー」(書こ+う → カコ'ー / でしょ+う → デ'ショー)。
    「思う」は 1 語エントリなので対象外
12. 形容詞「無い」は助詞の後ろでは自立語として新しい句を始める
    (行か+ない → イカナイ / 時間+が+ない → ジカンガ|ナ'イ / 学生では+ない → ガクセーデ'ワ|ナ'イ)

### 3.3 連接コストの近似 (engine.js `_connCost`)
- 名詞 (NOUN_POS) の直後に動詞活用語尾 す/る/れ/せ/ろ/ください が来る連接に 5000 のペナルティ。
  公式: 「遊んでいます」= アソンデ + イマ'ス (= い+ます)。cost 和では いま(2377)+す(6951)=9328 が
  い(6811)+ます(3912)=10723 より安く誤るため。
- Viterbi が語の**全レコード**を連接コスト込みで評価するようにした (文脈で読みが変わる語の布石)。

### 3.4 辞書デコードのバグ修正
- accent バイトは **5bit** (`& 0x1f`)。既存の `& 0x3f` はバグで、し/さ/す/な 等 34 レコードが
  accent(32/33) > mora になっていた (5bit なら全 384657 レコードで 0 件)。
- `decodeRecords` に `pos` を追加し `toKanaDetailed`/`reading` で `pos`/`cost` を公開 (追加フィールドのみ)。

| 仮説 | 結果 |

| 自立語+自立語を無条件に複合語として 1 句にまとめる | DEV 48.6%→**13.6%** (大幅悪化)。「ちょっと+待っ」「新しい+仕事」等を誤結合 |
| 名詞+名詞の複合 (時間名詞・形容詞の pos を混入させたまま) | DEV 79.3%→**70.0%** (13 文悪化)。pos 集合の誤分類が原因と判明し修正後は 87.1% へ |

## 5. 残る誤り (DEV140 で 18 文)

**(a) 語の選択 (連接コスト由来) — 約 8 文**
公式は品詞間連接コストで形態素を選ぶ。cost 最小では選べない例:
- 十年前 → ジュ'ーネンマ'エ (我々: ジュー+トシ+ゼン)、寝る前 → ヌルヌ'エ (我々: ゼン)
- 何度も → ナ'ンドモ (我々: ナニ+ド)
- 昨夜は → ユンベ'ワ (我々: サクヤ)
- 雪が → ユキ'ガ (我々: ソソガ = 1 語エントリ)
- 行って → イッテ (我々: オコナッ+テ)
- 買いに (文脈依存の核)、休み (a3→a2)、晴れ (a2→a1 の文脈依存)
→ 品詞連接コスト表の本格的な復元 (または公式出力からの学習) が必要。

**(b) 分かち書き — 約 4 文**
- 話して (1 語) vs 話し+て、たばかり vs た+ばかり、せまし vs せ+まし、読み終わったら

**(c) アクセント句/核の未解明 — 約 4 文**
- 「〜てから」の句、については+後+で、食べて+みたい (みたい a1 vs a2)、
  「〜ている」の `+` 境界 (降っている = フ'ッテ+イル'ノデ / 遅れている = オクレテイル'ノデ)
- 「後」= ゴ vs アト、「うと」= 1 語 vs う+と

## 6. 次の一手 (提案)

1. **品詞連接コストの復元**。辞書レコードの「extra バイト」(mora の後ろ、可変長) が
   連接情報らしき構造を持っている (例: は/が = `60 83 a1`, た = `80 a2 c3`, ながら = `71 91 b1`)。
   まず MAP1/TOK1 以外のセクションと extra バイトの形式を確定させ、そこから連接行列を復元する。
   無理なら公式出力を大規模に取得し、連接コストを学習する (今回 `_official.mjs` で
   1 万句規模の対拍が現実的な時間で可能になった)。
2. **段/行/活用型の同定**。pos 値は活用の型を符号化しているらしく (例: 580 = ある/いる/なる/降る)、
   これが分かると「そうです」「ようです」の切れ目や、動詞+助動詞の核規則を pos で統一的に書ける。
3. **音読み/訓読みの選択規則**。漢語の連なりでは音読みが選ばれる傾向があるが例外 (前) がある。
   読みの「音/訓」属性が pos か extra バイトにあるはずなので、それを同定する。
4. コーパスをさらに拡大 (現在 DEV140 + 保留 87)。特にサ変動詞・複合動詞・助数詞を増やす。
